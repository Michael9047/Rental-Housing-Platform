## 1. 模块概述

### 1.1 定位

BM（Building Manager / 楼栋管理员）是房源供给侧的核心角色。本模块提供楼栋 → 户型 → 图片 → 员工的完整管理链路，以及通勤信息、周边 POI、地图集成等辅助功能。

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| 楼栋管理 | CRUD + 软删除（回收站）+ 恢复 + 彻底删除 |
| 户型/房型管理 | CRUD + 复制 + 租金定价 + 库存管理 |
| 图片管理 | 上传/排序/设主图/删除 |
| 员工管理 | 楼栋员工（前台/管家）的添加/编辑/删除 |
| 通勤信息 | 楼栋到各大学的通勤时间/路线配置 |
| 周边 POI | 自动生成（高德/Google）+ 手动补充 |
| 地图/地理编码 | 地址 → 经纬度（高德 + Google 双引擎） |
| 预约管理 | 查看租客对本楼栋的预约 + 更新状态 |
| 租客管理 | 查看/登记租客信息 |
| 数据看板 | 楼栋运营数据（预约数、入住率等） |
| 合同管理 | 查看/生成楼栋关联的合同 |
| 物理房间管理 | 房号库存 + 预约分配 |

### 1.3 三层改两层后的数据模型

```
旧架构（三层，已废弃）：    Property → Room → Booking
新架构（两层，当前）：       Institute → UnitType → Booking
                            (楼栋/公寓)  (户型/房型)  (预约)
```

| `user_favorites` | 租客户型收藏（UNIQUE user_id + unit_type_id） | →users, unit_types CASCADE |
| `room_inventory` | 物理房间库存（UNIQUE institute_id + room_number） | →institutes CASCADE, unit_types SET NULL |
| `booking_room_assignments` | 预约→房间分配审计（UNIQUE booking_id） | →bookings, room_inventory, users RESTRICT |

> 兼容别名：`PropertyImage` → `BuildingImage`，`RoomCommute` → `InstituteCommute`，`PropertyPOI` → `InstitutePOI`，`RoomType` → `UnitType`（通过 `_compat.py`）
