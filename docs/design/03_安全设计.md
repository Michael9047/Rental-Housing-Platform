## 1. 认证体系

### 1.1 认证方式

| 方式 | 实现 | 说明 |
|------|------|------|
| 密码登录 | bcrypt 哈希 + JWT | 用户设置密码后使用 |
| 短信验证码 | 阿里云 dypnsapi | 6 位数字，5 分钟有效，60s 发送冷却 |
| 微信扫码 | 微信开放平台 OAuth | Web 端扫码登录 |
| JWT Token | HS256 签名 | access_token 60min, refresh_token 7d |

### 1.2 登录流程

```
用户输入手机号 → 发送短信验证码（60s冷却）
                → 用户输入验证码
                → 后端校验 → 新用户自动注册 / 老用户直接登录
                → 返回 { access_token, refresh_token, user }
```

### 1.3 Token 管理

- **access_token**：60 分钟有效期，存前端内存（Pinia store），不持久化
- **refresh_token**：7 天有效期，存 localStorage，仅在 `/auth/refresh` 端点使用
- **吊销**：当前为无状态 JWT，无服务端吊销。后续版本可通过 Redis 黑名单实现
- **续期**：前端 axios 拦截器在 401 时自动尝试 refresh

## 2. 权限模型

### 2.1 RBAC 四角色

```
                    ┌─────────┐
                    │  admin  │  全部权限
                    └────┬────┘
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   ┌────▼────┐    ┌─────▼──────┐   ┌─────▼──────┐
   │   bm    │    │   tenant   │   │maintenance │
   │ 楼栋管理 │    │   租客      │   │  维修工人   │
   └─────────┘    └────────────┘   └────────────┘
```

### 2.2 资源所有权

| 资源 | 所有者 | 访问规则 |
|------|--------|----------|
| 楼栋 (institute) | BM | BM 只能操作自己的楼栋，admin 可操作全部 |
| 预约 (booking) | Tenant | 租客只能查看自己的预约，BM 可查看所属楼栋的预约 |
| 订单 (order) | Tenant | 租客只能查看自己的订单 |
| 维修工单 (repair) | Maintenance Worker | 维修工只能查看分配给自己的工单 |

### 2.3 角色边界（不能越权）

```
tenant  ❌ 不能访问 /buildings/* (POST/PATCH/DELETE)
bm      ❌ 不能访问 /admin/*
bm      ❌ 不能操作其他 bm 的楼栋
maintenance ❌ 不能访问 /bookings, /payments
```

## 3. API 安全

### 3.1 认证保护

- 绝大多数端点需要 `Depends(get_current_user)`
- **8 个公开端点缺认证**（详见 08-08 审计报告 H-SEC-1）：`/buildings/{id}/staff`、`/geo/geocode`、`/commute/*`、`/pois/*`、`/tenants/{id}`、`/users` (POST)——这些端点目前消耗付费 API 配额或暴露敏感数据

### 3.2 速率限制

- 实现：Redis 令牌桶，按 IP + 端点前缀
- 默认：100 次 / 60 秒
- **已知问题**：Redis 不可达时静默跳过，限流失效——需加 fallback 日志告警

### 3.3 CORS

- 开发环境：`localhost:5173, :8080, :8012`
- 生产环境：由 `CORS_ORIGINS` 环境变量指定
- **已知问题**：`allow_headers=["*"]` + `allow_credentials=True` 组合违反 CORS 规范

### 3.4 输入校验

- 所有请求体使用 Pydantic `Field()` 约束
- 文件上传：Content-Type 白名单 + 大小上限 5MB + UUID 文件名

## 4. 数据安全

### 4.1 PII 保护

| 字段 | 存储 | 传输 | 日志 |
|------|------|------|------|
| 密码 | bcrypt 哈希 | 不传输（TLS 保护请求体） | 禁止记录 |
| 手机号 | 明文（业务需要） | TLS | 脱敏（`mask_sensitive` 函数） |
| 邮箱 | 明文（业务需要） | TLS | 脱敏 |
| 身份证号 | 暂不收集 | — | — |
| 人脸数据 | 暂不收集 | — | — |

### 4.2 敏感字段脱敏

`backend/app/core/logging.py:26-29` 已实现自动脱敏：
- `password`, `phone`, `email`, `secret`, `token`, `authorization`, `cookie` 字段自动替换为 `***`
- 日志中的手机号和邮箱格式自动正则替换为 `[PHONE]`、`[EMAIL]`

### 4.3 前端安全

| 问题 | 现状 | 风险 |
|------|------|------|
| localStorage 存储 User 对象 | ✅ 已修复（仅存 token） | — |
| API Key 打包到前端 bundle | ❌ `.env` 中 `VITE_AMAP_KEY` + `VITE_GM_KEY` 编译进 JS | 任意访客可在浏览器 Source 面板获取 |
| console 日志泄露 PII | ❌ `PersonalInfo.vue:184` 在 console.error 中打完整 payload | 浏览器控制台可查看上一个用户个人信息 |

## 6. 合规注意事项

| 法规 | 适用范围 | 影响 |
|------|----------|------|
| 《个人信息保护法》 | 收集手机号/邮箱 | 需在隐私政策中明示用途，用戶可查询/删除 |
| 《网络安全法》第 24 条 | 提供信息发布服务 | 用户需提供真实身份信息（本平台通过手机号验证满足） |
| 《电子签名法》 | 留房确认协议 | 点击确认+短信验证码满足"可靠电子签名"约定条件 |
