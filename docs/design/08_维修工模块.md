## 1. 模块概述

### 1.1 定位

维修工模块为维修工人（Maintenance Worker 角色）提供工单生命周期管理：接收工单 → 确认接单 → 开始维修 → 完工上报 → 管理员确认。同时 BM 可以通过工作台管理自己楼栋的维修工和派单。

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| 工单创建 | 租客/BM 提交维修申请（描述 + 图片 + 问题类型） |
| 工单分配 | BM/Admin 将工单分配给维修工 |
| 工单处理 | 维修工：接单 → 开始维修 → 完成（填写工作记录 + 图片） |
| 工单确认 | 租客/BM 确认维修完成 |
| 维修工管理 | BM 添加/编辑/调整维修工状态 |
| 工作台 | 维修工视角的待处理工单 + 统计数据（`/maintenance/dashboard`） |

## 2. 工单状态机

```
                     pending (待分配)
                        │
                   assign│(BM 分配维修工)
                        ▼
                     assigned (已分配)
                        │
                 start  │(维修工接单)
                        ▼
                   in_progress (维修中)
                        │
               complete │(维修工完工，填写 work_record + work_images)
                        ▼
                    completed (待确认)
                      /         \
             confirm │           │ cancel (租客取消)
                    ▼            ▼
                 confirmed     cancelled
                 (已确认)      (已取消)

特殊状态：
  pending_escalated (已升级) — 维修工无法处理，升级给 Admin
  rejected (已拒绝) — BM 拒绝工单
```

## 3. 后端设计

### 3.1 路由清单

> 以下数据来自实际代码，2026-08-10 提取。基础路径 `/api/v1`。

#### 维修工单

| 方法 | 路径 | 权限 | 请求 Schema | 响应 Schema | 说明 |
|------|------|------|------------|------------|------|
| POST | `/repairs` | tenant | `RepairCreate` | `RepairRead` | 创建维修工单 |
| GET | `/repairs` | user | query: status, skip, limit | `list[RepairRead]` | 工单列表（按角色过滤：租客看自己，BM 看属下，维修工看自己被分配的） |
| GET | `/repairs/pending-escalated` | admin | — | `list[RepairRead]` | 查看已升级待处理的工单 |
| GET | `/repairs/{repair_id}` | user | — | `RepairRead` | 工单详情 |
| PATCH | `/repairs/{repair_id}/status` | landlord | query: new_status | `RepairRead` | 更新工单状态（BM 端：审批/拒绝） |
| PATCH | `/repairs/{repair_id}/assign` | landlord | query: worker_id | `RepairRead` | 分配工单给维修工 |
| PATCH | `/repairs/{repair_id}/start` | maintenance | — | `RepairRead` | 接单（开始维修） |
| PATCH | `/repairs/{repair_id}/complete` | maintenance | query: work_record | `RepairRead` | 完工上报（含工作记录） |
| PATCH | `/repairs/{repair_id}/cancel` | tenant | — | `RepairRead` | 取消工单 |
| PATCH | `/repairs/{repair_id}/confirm` | tenant | — | `RepairRead` | 确认维修完成 |

| 分配工单 (`assign`) | ❌ | ✅ | ❌ | ✅ |
| 审批/拒绝 (`status`) | ❌ | ✅ | ❌ | ✅ |
| 接单/开始 (`start`) | ❌ | ❌ | ✅（自己的单） | ❌ |
| 完工上报 (`complete`) | ❌ | ❌ | ✅（自己的单） | ❌ |
| 确认完成 (`confirm`) | ✅（自己的单） | ✅ | ❌ | ✅ |
| 取消工单 (`cancel`) | ✅（自己的单） | ✅ | ✅（自己的单） | ✅ |

### 3.4 关键 Schema

> 文件 `backend/app/schemas/repair.py`

**工单**

| Schema 类 | 用途 | 关键字段 |
|-----------|------|----------|
| `RepairCreate` | 创建工单 | `property_id: int`, `issue_type: RepairIssueType`, `description: str`, `images: list[str]\|None`, `scheduled_time: str\|None` |
| `RepairUpdate` | 更新工单 | `status: RepairStatus\|None`, `assigned_worker_id: int\|None`, `work_record: str\|None`, `work_images: list[str]\|None` |
| `RepairRead` | 工单响应 | `id`, `property_id`, `tenant_id`, `landlord_id`, `assigned_worker_id`, `issue_type`, `description`, `images`, `status`, `scheduled_time`, `completed_at`, `work_record`, `work_images`, `created_at`, `updated_at`, `tenant_name`, `landlord_name`, `worker_name`, `property_title` |

**维修工**

| Schema 类 | 用途 | 关键字段 |

| `WorkerUpdate` | 编辑维修工 | `phone: str\|None`, `skills: list[str]\|None` |
| `WorkerStatusUpdate` | 调整状态 | `status: WorkerStatus` |

**枚举**

| Enum | 取值 |
|------|------|

| `RepairStatus` | `pending`, `pending_escalated`, `assigned`, `in_progress`, `completed`, `confirmed`, `rejected`, `cancelled` |

## 6. 异常处理

| 场景 | HTTP 状态码 | 用户提示 |
|------|------------|----------|
| 工单不存在 | 404 | "工单不存在或已被删除" |
| 无权操作此工单 | 403 | "您无权操作此工单" |
| 状态不允许此操作 | 409 | "工单当前状态不允许此操作"（如已完成的工单不能再接单） |
| 维修工已被停用 | 400 | "该维修工已被停用，无法分配工单" |
| 维修工已有进行中工单 | 409 | "该维修工尚有未完成工单" |
| 升级工单无权限 | 403 | "仅维修工可升级工单" |
