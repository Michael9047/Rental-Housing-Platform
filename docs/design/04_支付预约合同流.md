> 版本：v1.0 | 日期：2026-08-10 | 作者：[同学 A]

## 1. 模块概述

### 1.1 定位

支付预约合同流是租客端的核心业务流程，覆盖从"预约看房 → 支付留房手续费 → 签署留房确认协议 → 获取合同"的完整链路。

### 1.2 核心功能

| 功能 | 说明 |
|------|------|
| 预约流程 | 多步骤表单：选择日期 → 个人信息 → 紧急联系人 → 信息确认与授权 → 支付 → 结果 |
| 草稿保存 | 每一步自动保存草稿（BookingFlowDraft），支持断点续填 |
| 押金/手续费支付 | 对接支付网关，支持模拟支付 + 微信支付 + 银行卡（后续） |
| 留房确认协议 | 点击确认 + 短信验证码 → 签署电子协议 |
| 消息通知 | 预约创建、支付成功、合同生成等节点发送站内通知 + SMS/邮件 |
| 合同生成 | 基于模板填充用户/房源数据生成 PDF 合同 |
| 租客档案管理 | 跨预约复用的租客个人信息档案 |
| 房号确认 | BM 确认支付后的订单房号 → 触发合同生成 |

## 2. 业务流程

### 2.1 预约→支付→合同 时序图

```
租客(前端)               后端API               DB               外部服务
  │                       │                   │                   │
  │ PUT /bookings/drafts/{unit_type_id}        │                   │
  │ (选择日期, 户型)        │ ──创建/更新草稿──▶ │                   │
  │                       │                   │                   │
  │ POST /bookings/personal-info/validate      │                   │
  │ (校验个人信息)          │ ──校验字段────────▶ │                   │
  │                       │                   │                   │
  │ POST /bookings/emergency-contact/validate  │                   │
  │ (校验紧急联系人)        │ ──校验字段────────▶ │                   │
  │                       │                   │                   │
  │ POST /bookings/confirm │                   │                   │
  │ (确认信息 + 同意协议)    │ ──创建预约+订单──▶  │                   │
  │                       │ ──发送通知────────┼──▶ 通知服务(SMS/邮件) │
  │                       │                   │                   │
  │ 跳转支付页              │                   │                   │
  │ POST /payments/create  │                   │                   │
  │                       │ ──创建支付单──────▶ │                   │
  │                       │ ──调用支付网关────┼──▶ 支付网关          │
  │                       │                   │                   │
  │ 用户在支付页完成支付     │                   │                   │
  │                       │ ◀──webhook回调────┼────────────────────│
  │                       │ ──更新订单状态────▶ │                   │
  │                       │                   │                   │
  │ BM 确认房号             │                   │                   │
  │ POST /room-confirmations/{booking_id}/confirm                   │
  │                       │ ──确认房号+生成合同▶ │                   │
  │                       │ ──发送通知────────┼──▶ 通知服务          │
  │                       │                   │                   │
  │ 跳转结果页              │                   │                   │
  │ (显示合同下载链接)       │                   │                   │
```

### 2.2 状态机

```
预约状态 (BookingStatus):
  pending → approved / rejected / cancelled / completed
  → payment_pending → payment_processing → paid / payment_failed / payment_expired
  → paid → contract_ready → completed
  → refund_pending → refunded / payment_review

支付状态 (PaymentStatus):
  pending → processing → success / failed / closed / expired
  → review → refund_pending → refunded

订单生命周期（booking.status 承载）:
  创建 → 支付 → BM确认房号 → 合同生成 → 完成
```

## 6. 异常处理

| 场景 | HTTP 状态码 | 用户提示 |
|------|------------|----------|
| 日期不可选 | 409 | "该入住日期已无可用房源" |
| 草稿信息不完整 | 422 | "请先完善[某步骤]信息" |
| 支付金额不匹配 | 400 | "支付金额异常，请刷新重试" |
| 支付超时 | 408 | "支付已超时，请重新发起" |
| 支付渠道故障 | 503 | "该支付方式暂不可用" |
| 合同模板缺失 | 500 | "合同模板未配置，请联系客服" |
| 重复支付 | 409 | "该订单已支付，请勿重复操作" |
| 重复签名 | 409 | "该合同已签署"（idempotency_key 去重） |
| 签名内容哈希不匹配 | 400 | "合同内容已变更，请刷新后重签" |
| 房号已被占用 | 409 | "该房间已被其他预约占用" |
