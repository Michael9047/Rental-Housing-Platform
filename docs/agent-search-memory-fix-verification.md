## 3. 实际交互记录

下面同时保留了“修复前复现”和“修复目标/回归断言”，便于以后再次检查。

### 场景 A：固定欢迎语、FAQ 和长输入

**打开页面：** `/ai-search`

页面固定展示：

- “你好，我是租房推荐管家 👋”
- NUS、预算、健身房/自习空间、房源比较四个固定入口。
- 输入框上方 FAQ chips。
- 左侧“对话记录”和“长期记忆”。

**输入：** 20,000 个字符。

**实际结果：** 输入框显示 `20000 / 20000`，发送按钮可用；输入内容不再被 4,000 字旧限制截断。

### 场景 B：FAQ

**我问：** `预订流程`

**系统实际答复：**

> （以下为占位说明，正式政策以平台最新规则与合同条款为准；如有疑问请联系客服。）预订流程大致是：在房源详情页选择入住日期并提交申请；房东确认后支付押金锁房；双方在线签署合同；之后可在“我的预订”查看状态。

**判断：** 通过。回答命中 FAQ，且没有把占位政策当成正式承诺。

### 场景 C：NUS Studio 初次推荐

**我问：** `找 NUS 附近的 Studio`

**修复前复现：** 返回 5 套，除 NUS 外还混入 UCL、UCLA、HKU；本轮状态只记录了 `studio`，没有稳定保留 NUS/SG。

**修复后的回归要求：**

- 查询应解析为 NUS/新加坡，并保留 `institution=NUS`、`country=SG`。
- 推荐卡片出现在正文上方。
- 结果不得混入英国、美国或中国香港房源。
- 若数据库没有足够 NUS Studio，应如实说明数量，不得用跨国房源凑满。

### 场景 D：上一轮房源的健身房追问

**我接着问：** `你推荐的这个有健身房嘛？`

**修复前复现：** 系统把它当成新的“Studio + 健身房”全局搜索，返回 NUS 和 UCLA 两套，没有只回答上一轮首套。

**修复后的答复规则：**

- “这个”解析到上一轮第一套 NUS 房源，并在回答中明确房源名称。
- 设施清单明确包含健身房时回答“明确有”。
- 清单没有列出时回答“当前清单未列出”，不能擅自断言一定没有。
- 设施数据缺失时回答“暂时无法确认，建议向公寓核实”。
- 这类事实追问不重新进行跨国房源搜索。

### 场景 E：附近自习空间

**我接着问：** `这个房子附近有自习室吗？`

**修复前复现：** 系统把楼内 `自习室` 设施当成“附近自习室”回答；同时卡片又显示“周边数据待补充”，事实口径冲突。

**修复后的答复规则：**

- 若楼内设施列有自习室，可以明确说“楼内有自习室”。
- “附近/边上”必须查询周边 POI；当前没有 POI 数据时明确说“楼外附近暂无可核实数据”。
- 不得把楼内设施伪装成附近独立场所。

### 场景 F：筛选结果直接比较

**页面条件：** 搜索页当前显示前 5 套 NUS 房源。

**我问：** `这几套哪个好？`

**系统实际答复摘要：**

> 5 套都在金文泰。通勤数据缺失，因此主要比较价格和空间。Ensuite 价格最低、综合最均衡；Studio 空间稍大且价格居中；两室一厅空间最大但价格明显更高。系统随后列出了每套的价格、面积、房型、数据缺失项和综合排序。

**判断：** 通过。请求携带当前页面前 5 套 ID，没有再错误比较候选清单中的其他房源；长回复通过流式展示完成。

### 场景 G：国家/地区筛选

**操作：** 在 `/search` 选择 `🇸🇬 新加坡`。

**修复前复现：** 选择器已显示新加坡，但旧运行后端仍返回 24 套并包含伦敦房源。

**修复后的回归要求：**

- 请求携带 `country=SG`。
- 后端在 Property/UnitType/Institute 三层数据上统一按国家过滤。
- 结果不得包含 GB/US/HK/CN/AU 房源。
- 切换国家时清掉旧地区，选择 NUS/NTU/UCLA 时同步正确国家。

### 场景 H：对话记录和长期记忆

**操作步骤：**

1. 完成一轮 NUS、预算、Studio 对话。
2. 点击“保存本次偏好”。
3. 点击“新对话”。
4. 刷新页面并切回上一条历史会话。

**回归要求：**

- 侧栏显示会话标题、最近消息和更新时间。
- 切换会话可恢复用户与 Agent 的历史消息。
- 新对话仍能读取用户显式保存的地区、预算和户型偏好。
- 清空长期记忆后，新对话不再自动带入这些偏好；历史会话本身不被删除。

## 5. 事实边界与注意事项

- “周边有自习室”只有在存在可核实 POI 数据时才能肯定；楼内自习室和楼外附近场所是两个不同事实。
- 通勤、周边距离、评价等字段缺失时，回答必须显式说明缺失，不能用模型猜测。
- FAQ 中合同、押金、退款等目前是占位说明，正式上线前需要业务方确认政策文本。
- 本地浏览器验收使用了不含真实个人信息的临时租客账号。
- 数据库模型新增后需先执行 Alembic 迁移，再重启后端服务，才能完整使用会话状态和长期记忆接口。
