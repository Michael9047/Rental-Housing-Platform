# 公寓与户型生命周期操作说明

## 状态与操作

- 公寓 `active` 表示已上架，`offline` 表示主动下架，`pending` 表示资料待完善，`suspended` 表示已进入回收站。
- 户型 `available` 表示已上架，`offline` 表示主动下架，`maintenance` 表示维护中，`rented` 表示不可新增预订。
- 公寓下架只在租客查询层遮蔽其户型，不改写户型本身的状态；重新上架后，原本可租的户型自动重新可见。
- 下架不会取消或修改已有订单，订单详情、合同、支付及租客资料仍按订单自身状态处理。

## 上架资料要求

公寓上架要求名称、国家/地区、城市、街道、经纬度和至少一张图片。户型上架要求公寓关联、户型类型、租金、币种、总库存、可租库存、最早可入住日期和图片。

## 删除与回收站

- 删除和下架是不同操作；日常停止获客应使用“下架”。
- 存在订单等业务历史时禁止删除，只允许下架。
- 公寓进入回收站时记录本次实际级联删除的户型，恢复时不会误恢复此前单独删除的户型。
- 永久删除仅允许进入回收站满 30 天且不存在业务历史的对象。

## 库存口径

- `total_count` 为户型总套数，`available_count` 为可接受新订单的套数，必须满足 `0 <= available_count <= total_count`。
- 管理页“生效订单”来自合同已签署、待支付、支付处理中及已支付订单的聚合，不再用“总套数减可租套数”推算。
